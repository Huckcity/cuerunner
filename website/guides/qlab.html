Coming from QLab

A QLab show comes across in one step: from the workspace file, or from QLab itself while it is running. The cues keep their numbers, names, colours, notes and timing, and a report says, cue by cue, what could not come across exactly.

1. From the workspace file

Cuerunner ▾ → Import QLab Workspace… → Choose Workspace File…, and pick the .qlab5. A .qlab4 and a .cues file work the same way. A workspace saved as a folder can be picked by the file inside it.

The show opens as a new show with no file of its own. Nothing is written to the QLab workspace or beside it. Save As keeps the new show where you choose, and closing without saving asks first, as it does for any show with unsaved changes. The audio device, MIDI port and other settings of this computer stay as they were: a QLab show's outputs name another machine's hardware.

Audio plays from where QLab kept it. QLab records each file relative to the workspace, so copy the workspace together with its audio folder and every cue plays straight away.

2. From a running QLab

For a show on a Mac you can reach over the network, a workspace whose last changes were never saved, or a QLab version whose files the import does not read. Cuerunner asks QLab for the show over QLab's own OSC interface, cue by cue.

  1. In QLab's workspace settings, let this computer in over OSC, with the workspace's passcode if it has one.
  2. In Import QLab Workspace…, type the Mac's address (127.0.0.1 if QLab is on this computer) and the port, which is 53000 unless it has been changed.
  3. Find Workspaces, pick one, type the passcode if it asks for one, and press Import from QLab.

The file paths QLab reports are where the audio is on that Mac, so the report lists the files as missing. Copy the show's audio folder across and use Find in Folder…, below.

3. Read the report

The report opens as soon as the show does. It lists every QLab cue type in the show, how many cues of it there were, and what each became. Below that, by cue:

HeadingWhat it means
PlaceholdersCuerunner has no cue of this kind yet: video, camera, text, light, live input, MIDI file, timecode, the start/pause/load/reset/go-to/target/arm/disarm cues, and AppleScript. Each is a disarmed wait cue under the QLab cue's own number and name, so the running order keeps its shape, and its notes say what it was and carry what it held — the script, the light command, the file, the cue it targeted. Nothing is dropped.
ApproximatedMapped, with one thing that could not be carried exactly: a level above unity, a fade of level and pan at once, a group whose children chain in a way no Cuerunner mode does, a network patch that does not say where it sends. The line says which.
RetimedFires at the moment it fired in QLab, with its times written differently. See timing.

Audio files says whether every file the show plays was found. For the ones that were not, Find in Folder… asks for a folder — the show's audio folder, a copy of it, a stick — and links every missing file it holds at once. It looks for each file by the path QLab knew it by, then by the last few folders of that path, then by its name, and never searches: two files with one name in different folders are never mistaken for each other. The bar across the top of the window relinks one file at a time, as it does for any show.

Timing

Do not continue is Advance None, auto-continue is On start and auto-follow is On end.

QLab's auto-continue fires the next cue a post-wait after this one starts acting. Cuerunner's On start fires the next cue the moment this one is fired, and reads no post-wait. So the next cue's pre-wait is written to include this cue's pre-wait and post-wait, which puts it at the same moment, and the report lists it as retimed. A group whose children auto-continue into each other becomes a timeline with each child where the chain reached it.
