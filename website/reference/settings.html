Settings

Ctrl/⌘ + ,, or Cuerunner ▾ → Settings…, whose sidebar splits them by where they are kept: this show travels in the .cuerunner file, this computer stays on the machine.

General

ExclusiveoffKeeps other apps off the device, for every channel it has and steadier timing. A driver that refuses says why.

Under them, what the engine is actually doing: backend, rate, device, latency, voices playing, media memory, and any dropouts. That block is a reading, not a setting. Under it sits Reconnect device, which sends the show's settings to the engine again so a device it lost is reopened — a no-op while the device is already running them, and the way back once the interface is plugged in again. It is disabled while the engine runs a backend with no device at all, where a device request can only be refused.

License

Cuerunner Pro on this machine. The first table is what a machine is carrying once a key is on it, and the second is how a key is entered. Nothing on the tab is needed to run the free half, and nothing is asked of the network — the key is checked on the machine it is entered on, so a venue with no internet unlocks exactly like any other.

RowWhat it shows
LicenseWho the key is licensed to, as the issuer wrote it.
Key idThe key's own id, as the issuer minted it — what a question about this key is answered by.
IssuedThe day the key was issued.
ExpiresThe last day it runs, or never for a key with no end date.
DeactivateA button that takes the key off this machine: it goes back to the free half, and the shows are untouched.

A key that has run out leaves the Pro half off until a renewed one is entered, and the tab says which day it ran out. The cue stack and the shows keep working either way.

RowWhat it does
License keyThe field a key is pasted into. It is checked on this machine, so a show computer never needs the internet.
ActivateChecks what is in the field and turns the Pro half on the spot. A key that is refused says why, under the field.

Show Settings

The settings under Cuerunner ▾ → Show Settings… are the show's own, and travel in the file.

TabWhat is on it
ChannelsThe desk connection — OSC, MIDI or MIDI over TCP, with its address, the MIDI-over-TCP port being 51325 as an SQ and an Avantis both serve it — the channel strips on the console and the faders the show drives, each with a Count beside its heading that sizes the list. An SQ is opened on its own control service as well — TCP 51326 outbound, kept alive with a datagram to the desk's UDP 51324 — because its MIDI service carries the mutes and nothing else: the membership has no route there. A shorter strip count drops the last strips, which leaves every scene and unpatches whoever was on them; a shorter fader count drops the last faders and takes every scene's row for those places with them, and unpatches nobody. A strip is a name and a number — the per-channel fader select this tab used to carry is deleted, not deprecated — and which fader it rides is the scene's decision, made in the Scenes grid, so a show sets up its channels and its faders here and places them scene by scene. Each fader carries one desk number, for a desk that counts its DCAs differently from the show. Under the faders, Allow a channel to ride more than one fader is the rule the grid follows: off, placing a strip on a row takes it off that scene's other rows, and a recall folds whatever a file still carries down to the lowest-numbered fader. The line under the connection reads back exactly what will be sent, and names a show larger than the desk model states, with the number of inputs it exceeded. A recall that fails says which failure it was: nothing answered at that address, or the desk took the connection and reset it. The second is what a desk whose MIDI port another program is holding does, and there the address is right.
CastPerformers, their parts, the channel each is on, and any note. Groups are built in the Scenes view, from the strips a row should carry.
Mic plotPacks, the channel each is patched to, and who is wearing it. Changing a performer on a pack records a swap.

The Channels tab's own controls, in the order the tab shows them:

ControlWhat it sets
ModelWhich desk this is — any desk's note on and note off, an SQ, or an Avantis — and so what the desk takes as an open and a close.
HostThe desk's address, the one thing nobody can guess.
PortThe desk's MIDI-over-TCP port, 51325 on an SQ and on an Avantis, or the port an OSC desk's addresses are sent to.
AddressThe OSC address a fader is sent to, with {n} standing for its number.
ChannelThe MIDI channel the desk's own MIDI is set to — Utility → General → MIDI on an SQ.
GO buttonThe mute group the operator's GO key is assigned to at the desk, or no GO button for a show run from the window.
BACK buttonThe mute group the operator's BACK key is assigned to.
GO noteThe MIDI note the operator's GO key transmits, for a soft key set to MIDI Note — a press that steps the show once and leaves nothing lit. Offered on an SQ, whose own traffic cannot be a note.
BACK noteThe MIDI note the operator's BACK key transmits.
CountSizes the list beside it: the strips under the Channels heading, the faders under the DCAs one. A shorter count drops the last of them.
Allow a channel to ride more than one faderThe rule the Scenes grid follows: on, a strip rides as many faders as a scene places it on; off, the grid keeps one fader per channel and a recall folds a leftover down to the lowest-numbered one.

The desk's own buttons are read from the same connection, so they are set up with it: the two groups above are the mute groups the operator's GO and BACK keys are assigned to at the desk, and the two notes are for soft keys set to MIDI Note — offered on an SQ, whose own traffic cannot be a note. An Avantis answers for its keys four channels above its own, so a desk set to MIDI channel 13 or higher leaves them past what MIDI has: the fields are not drawn there, the show is run from the window, and a recall still sends.
